# 技能运行契约（skill-contract）
> 本文件防止的失败模式：触发边界含糊导致技能该触发时不触发、不该触发时抢活；领域研究、表面、输入输出、验收、边界、本地能力六类约束散落在各处而没有单一契约来源，导致每次运行口径不一致。

## 1. Trigger Contract

### 1.1 Should Trigger

命中以下任一条即应触发（给的是判定样式，不是穷举词表）：

| 场景 | 触发样式（用户原话或任务形态） |
| --- | --- |
| 陌生领域体系化研究 | "帮我从零搞清楚 X 这个领域""这个方向我没有基础，需要一份体系化梳理" |
| 行业深度调研 | "做一份 X 行业的深度调研""这个赛道现在什么情况，要有来源" |
| 内容 / 课程 / 产品前期论证 | "我要做一门 X 课程，先论证一下值不值得做""产品立项前先把这块调研清楚" |
| 课题研究 | "这个课题要交研究报告，需要可追溯的资料" |
| 交付物形态信号 | 明确要求"文档 + 可交互 HTML 两版""结论要有证据编号 / 可点开来源" |

### 1.2 Should Not Trigger

| 场景 | 判定 | 应走 |
| --- | --- | --- |
| 一次事实确认 | "X 是哪一年发布的" | 普通搜索 |
| 单篇内容总结 | "把这篇链接总结一下" | 阅读/总结 |
| 纯写作 / 改写 / 润色 | 已有材料，只要成文 | 写作类技能 |
| 纯计算 / 代码任务 | 无外部事实需求 | 对应工程技能 |
| 发布 / 投放 / 付费动作 | "发出去""帮我买" | 拒绝越界动作（本技能不做） |

### 1.3 Near-Miss

近似但**不触发本技能**，必须显式给出路由理由：

| 近似请求 | 为什么不触发 | 路由到 |
| --- | --- | --- |
| "快速查一下 X 和 Y 哪个好"（≤1 次检索、单一工具、不要交付物） | 不需要三级协同、不需要证据 ID 体系 | `tavily-research` 或快速检索 |
| "给我一份 X 的概览"（要速度，接受无溯源） | 无溯源要求 ⇒ 证据模型不适用 | `tavily-research` |
| "帮我核实这句话对不对" | 单点核实，无体系化产出 | 单次检索 + 引文 |
| "把已有材料整理成报告"（材料已齐、无需外部检索） | 无外部取证需求 | 写作/整理类技能 |
| "写一个 HTML 页面"（无调研） | 无研究过程 | 前端/设计类任务 |

**路由边界（硬规则）**：**只要一次快速检索或单工具研究 → 走 `tavily-research`；需要三级协同 + 双交付物 + 证据 ID 体系 → 走本技能 `deep-research-collab`。**

判定三问（全部为"是"才走本技能）：① 需要 ≥ 2 个层级/域（含中文域）的协同检索？② 需要文档版 + HTML 双交付物？③ 结论需要绑定证据 ID 并可溯源？

### 1.4 Ambiguous Handling

判定不清时，按以下顺序处理，**不得静默二选一**：

1. 先问一个澄清问题（不超过 1 个）："你要的是一次快速检索，还是需要带来源证据、可交付的双版本报告？"
2. 用户不答 / 无法回答时：按**最小充分原则**起步——先给 3 分钟可见结果（research brief），并声明"当前按轻量路径执行，若需要双交付物与证据 ID 体系，请回复确认升级"。
3. 升级路径：一旦确认需要双交付物或证据 ID 体系，即升级为本技能，并从阶段 0 重新走 `Domain Research Brief`（禁止在已有结论上补挂证据 ID 冒充合规）。
4. 降级路径：用户明确只要"快"，则移交 `tavily-research` 口径，并说明本次不产出证据库与 HTML。

## 2. Domain Research Contract

在任何检索、任何表面设计之前必须产出，字段清单如下（缺任一字段即禁止进入阶段 1）：

| 字段（固定名） | 内容 |
| --- | --- |
| `Raw user intent` | 用户原话逐字引用 + 一句话意图转述 + 意图类型 |
| `Suspected domain(s)` | 推断的领域（可有多个），每条标 `unverified` 或 `verified(EV-xxx)` |
| `Evidence read` | 已实际读过的在线证据判定（是否通过 `Online evidence read` 四项：链接可访问 / 有原文片段 / 有可归因主体 / 有时间戳）；无则写 `none` |
| `Evidence sweep attempted` | 已尝试过的检索与其层级（一级/二级/三级）、检索词、结果数量 |
| `Unavailable evidence paths` | 明确取不到的证据与原因（付费墙 / 需登录 / 官方未公开 / 本机无工具），每条给替代动作 |
| `Users` | 谁会读这份报告 |
| `roles` | `target roles`：报告接收者的角色功能（写变量，不写具体岗位名） |
| `Case variables that must not become fixed scope` | 本轮哪些具体值不得写进规则（公司名 / 行业名 / 一次性验收短语等） |
| `Native artifacts` | 该领域天然存在的产物形态（报告 / 白皮书 / 标准 / 数据集 …），用于确定报告形态 |
| `Work surfaces` | 本轮的表面：文档版章节树、HTML 交互控件、图表类型 |
| `tools` | 本轮使用的工具真名清单 |
| `Local capability inventory` | 实测能力表（字段见 `experience-surface-model.md` 第 5 节） |
| `Primary tool route` | 主检索路线（一级 → 二级 → 三级 的具体工具分工） |
| `Output evidence route` | 证据如何进入交付物（EV 编号 → 结论 → 图表 → 归档索引） |
| `Counterevidence` | 已知反证 / 预期反证来源；争议点必须正反并列 |
| `Research route: proceed \| research-needed \| blocked` | 三选一的最终判定及其理由 |

判定规则：

- `proceed`：字段齐全，且至少有一个待答问题已有 ≥ 2 条合格证据路径可达。
- `research-needed`：字段齐全，但核心问题证据不足；写缺口记录后**停止为该问题写结论**。
- `blocked`：字段无法齐全（缺用户材料 / 工具不可用 / 成本预算为 0）；向 `stakeholder` 说明所需材料与恢复条件。

## 3. Case variables

| 变量名 | 含义 | 默认值 |
| --- | --- | --- |
| `research_domain` | 研究领域/行业 | 由 `Raw user intent` 推断，标 `unverified` |
| `audience` | 阅读者及其知识水平 | `stakeholder_view` 所指向的读者 |
| `target roles` | 报告接收角色 | 未提供时，在 brief 中列为待确认项 |
| `stakeholder_view` | 决策视角（决定取舍口径与重点） | 未提供时按"决策支持"视角，并在 brief 中标注假设 |
| `deliverable_target` | 交付目标与用途 | 默认双交付物（Markdown + 单文件离线 HTML） |

约束：这些变量**默认写成变量**，不得把某个具体行业、公司、岗位写成规则；示例值必须标注"示例，不进入规则"。

## 4. Experience Surface Contract

| 契约项 | 内容 |
| --- | --- |
| 首屏 | 3 分钟可见结果：一页 research brief（研究主题 / 边界 / 指标体系 / 证据路线 / 交付物形态） |
| 可见中间产物 | `00-research-brief.md`、`01-candidate-sources.md`、`02-evidence-v1.0.md`、`03-cognition-map-v1.0.md`、`02-evidence-v2.0.md`、`03-cognition-map-v2.0.md` |
| 用户确认点 | P2 确认 brief；P3 确认报告结构；P4（可选）确认取舍口径 |
| 表面决定时点 | 必须在领域研究之后（Surface After Domain Research）：章节数 = 论证目标数，图表类型 = 结论类型分布 |
| 交付表面 | ① 文档版报告（Markdown）② 单文件离线 HTML 交互式报告（内嵌 SVG 图表 / 思维导图 / 流程图 / 证据链路；证据标签可点击跳证据库；支持按类型与可信度筛选 + 关键词检索） |
| 一致性 | 两版内容 100% 一致（结论句、数字、证据编号逐条比对） |
| 进度可见 | 每完成一个检索层级给一行进度（已用检索次数 / 剩余预算 / EV 数 / 缺口数） |

## 5. Input / Output Contract

输入（缺项时按"待确认"处理，不阻塞 brief 产出）：

| 输入 | 必填 | 缺失时 |
| --- | --- | --- |
| `原始意图`（用户原话） | 是 | 无法启动，先问 |
| `research_domain` | 否 | 由本技能推断并标 `unverified` |
| `audience` / `target roles` / `stakeholder_view` | 否 | 按默认值执行，在 brief 中标注假设 |
| `deliverable_target` | 否 | 默认双交付物 |
| 已有材料（内部文档 / 数据 / 链接） | 否 | 记入 `已知`，减少检索量 |

输出（**核心**交付物；完整清单与归档结构以 `references/research-workflow.md` §11 为准）：

| 产物 | 格式 | 关键要求 |
| --- | --- | --- |
| 文档版研究报告 | `report.md`（Markdown） | 结论绑定证据 ID；核心结论 ≥ 2 独立来源；争议点正反并列；`待补证` 小节对应 `research-needed` |
| HTML 交互式报告 | `report.html`（单文件、离线） | 内嵌 SVG；证据标签 `data-ev="EV-0xx"` 可点击跳转；类型/可信度筛选 + 关键词检索；与文档版 100% 一致；无无证据 ID 的结论 |
| 证据库 | `02-evidence-v2.0.md` | 每条 EV **十字段**齐全（证据 ID / 信息内容 / 类型 / 可信度 / 原文片段 / 来源标题 / 原始链接 / 提取时间 / 检索层级 / 检索工具） |
| 认知地图 | `03-cognition-map-v2.0.md` | 主题 → 子问题 → 结论 → 证据 ID 映射完整；含变更说明 |
| 归档包 | `archive/` + `manifest` | 含溯源索引与复现步骤；可单独复现结论 |
| 闭环运行记录 | `loop-run-record.md` | 本轮结论 / 证据缺口 / 写回决策 / 下一轮复用 key（六段结构见 `assets/loop-run-record-template.md`） |

## 6. Eval Contract

### 6.1 触发评测：5 正 5 负 3 近似 3 模糊

| 类别 | 条数 | 要求 |
| --- | --- | --- |
| 正例（Should Trigger） | 5 | 覆盖：陌生领域体系化研究 / 行业深度调研 / 内容或课程或产品前期论证 / 课题研究 / 明确要求双交付物与证据 ID |
| 负例（Should Not Trigger） | 5 | 覆盖：单次事实确认 / 单篇总结 / 纯写作润色 / 纯计算或代码 / 发布或付费动作 |
| 近似（Near-Miss） | 3 | 必须命中第 1.3 节路由规则，判给 `tavily-research` 或其它技能，并给出理由 |
| 模糊（Ambiguous） | 3 | 必须触发第 1.4 节澄清流程，并与用户确认后再定去留 |

通过判据：正例 5/5 触发；负例 5/5 不触发；近似 3/3 路由正确且理由可指认；模糊 3/3 先澄清、无静默二选一。

### 6.2 输出评测

| 评测项 | 通过判据 |
| --- | --- |
| 证据完整性 | 抽样 5 条 EV，字段齐全且链接可打开 |
| 来源合格 | 不存在"无链接 + 无原文片段"的外部事实 |
| 交叉验证 | 核心结论绑定 ≥ 2 个独立来源 |
| 争议并列 | 争议点正反证据同时存在 |
| 缺口处理 | 每个 `research-needed` 有补搜记录或明示披露 |
| 双版一致 | 逐条比对结论句 / 数字 / 证据编号，差异数 = 0 |
| HTML 合规 | 无无证据 ID 的结论；筛选与检索可用；离线可打开 |
| 成本 | 检索次数在预算内；秘塔约 3 积分/次与 Tavily 额度均已记录 |

### 6.3 基线对比

与基线对比，至少三项必须优于基线：① 可溯源结论占比；② 双版一致性缺陷数；③ 无证据断言数。基线定义：不使用本技能、单工具直接生成报告的默认流程。对比记录必须留下两份产物与逐项差异，禁止只写结论性描述。

### 6.4 回归

每次修改本包任一 reference 后必须回归：重跑 6.1 全量触发评测 + 6.2 输出评测；任一判据退化即回滚该次修改。回归记录包含：修改内容、受影响门禁、重跑结果、是否回滚。

## 7. Boundary Contract

| 边界 | 规则 | 越界时 |
| --- | --- | --- |
| 不伪造来源 | 不编造链接、标题、原文片段、时间 | 拒绝，给 `research-needed` 记录 |
| 不替代人工判断 | 不替 `stakeholder` 做取舍与决策 | 提供证据与选项，标注不确定度 |
| 不承诺无证据结论 | 无证据不写确定性结论；来源 < 2 不标核心结论 | 降级为"待验证判断" |
| 不做发布 / 付费动作 | 不发布、不投放、不下单、不代付费 | 交付文件，发布由用户执行 |
| 不越权取证 | 不绕付费墙、不抓取需登录内容 | 记入 `Unavailable evidence paths` |
| 不静默跳过缺口 | 关键缺口未补搜不得推进阶段 4 | 阻塞并披露缺口 |
| 不混合版本 | HTML 与文档版不一致即不合格 | 回退阶段 4 重做 |

## 8. Local Capability / Multimodal Contract

### 8.1 本地能力契约

- 设计任何表面之前，先实测 `Local capability inventory`；**未实测的能力不得写进证据路线**。
- 工具真名必须准确：Tavily CLI 可执行文件名是 `tvly`（**不是** `tavily`）；秘塔工具名为 `mcp__metaso__metaso_web_search` / `metaso_web_reader` / `metaso_chat` / `metaso_topic_list` / `metaso_topic_search` / `metaso_topic_file_content`。
- 成本边界：秘塔每次检索约 3 积分；Tavily 受计划额度上限约束。两者都必须写入 brief 的预算字段，并在触限时停止新增检索、转入输出阶段并披露证据覆盖度。
- 实测参考：`tvly` 可用（`tavily-cli 0.1.8`）；Chrome 可用（`C:\Program Files\Google\Chrome\Application\chrome.exe`，可做 HTML→PDF 与截图）；`python` 当前不在 PATH（NOT FOUND），执行 `python scripts/check_meta_skill_package.py .` 与 `python scripts/check_closed_loop.py .` 前需确认解释器路径/改用 `py -3`，不得因 not found 宣称校验通过。
- 能力不可用时走 `fallback`：降低检索层级、退化为对比表、或标 `blocked` 并说明所需材料。

### 8.2 多模态契约

| 模态 | 允许 | 禁止 |
| --- | --- | --- |
| SVG 图表 | 有来源的数据作图，标注来源 EV | 无来源量级作图；外部图片文件（必须内联） |
| 思维导图 | 分类体系，分支 ≤ 3 层 | 用导图掩盖证据缺失 |
| 流程图 | 阶段 / 决策链 / 转化路径，节点附 EV | 无 EV 节点的"漂亮流程" |
| 证据链路 | 结论 → EV → 来源 的连线 | 断链（结论无对应 EV） |
| 正反对置面板 | 争议点正反并列 | 单侧呈现 |
| 交互控件 | 按类型与可信度筛选、关键词检索 | 依赖外部 CDN 或联网资源 |
| 文档版 | 纯文本 Markdown，便于 diff 与版本对比 | 在 Markdown 中嵌入无法核验的图表结论 |

一致性硬约束：两版内容 100% 一致；HTML 中出现无证据 ID 的结论即不合格。
