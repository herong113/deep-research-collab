# 创建规则标准（creation-rule-standard）
> 本文件防止的失败模式：把技能包写成一堆松散的建议，缺少必需结构、把一次性验收细节写死成规则、阶段没有通过判据、失败没有出口，导致技能无法被跨会话复用，也无法被自动校验门禁验收。

## 0. 适用范围与优先级

本文件是本包内**顶级创建 / 重构规则标准**。任何新增或修改 reference / SKILL 正文的动作，先对照本文件，再动笔。

优先级：`Hard Stops`（第 7 节）> `Required Anatomy`（第 1 节）> 其它章节。发生冲突时，上位规则生效。

## 1. Required Anatomy

技能包正文必须含且仅含下列十二个结构字段。字段齐全才可提交评审；缺任意一项即为不合格。

| 字段 | 必须写什么 | 缺失后果 |
| --- | --- | --- |
| 触发边界 | Should Trigger（含中英触发词与用户原话样式）、Should Not Trigger、Near-Miss、Ambiguous Handling 四段；每段给可判定的句子样例 | 技能永不触发或被滥用触发，路由到错误的相邻技能 |
| 用户结果 | 用户拿到手的**具体产物形态**（文件名、格式、可打开方式）与"可看到结果的时点" | 技能退化为"给建议"，没有交付物，无法验收 |
| 范围 | 做什么 / 不做什么两列清单；不做什么必须逐条写清，不留"等等" | 边界漂移，被要求执行合约外动作（发布、付费、伪造来源） |
| 案例变量边界 | 见第 2 节；默认全变量化 | 某个具体行业/公司/岗位被写成硬规则，技能只能服务一个案例 |
| 证据模型 | 证据 ID 生成规则、字段清单、可信度判定、结论与证据的绑定规则 | 结论无法溯源，HTML 出现无证据 ID 的结论 |
| 阶段契约 | 见第 3 节四段式（Critical Thinking / Fetch / Deep Thinking / Review） | 没有通过判据，阶段推进会变成"感觉差不多了" |
| 产物链 | Artifact Chain：每一步的输入、产物文件名、完成判据 | 中间产物丢失，回退与复现不可能 |
| 工具路线 | 一级/二级/三级检索的工具真名与分工、成本口径 | 调用错工具（如把 `tvly` 写成 `tavily`），成本失控 |
| 决策面 | 需要人确认的决策点（受众、结构、取舍口径）与其默认值 | 长流程无人干预，方向错了才发现 |
| 验收标准 | Acceptance Matrix（见第 6 节） | 无门禁，无法判定 done |
| 失败处理 | 失败分类、降级路径、`writeback` 与 `none-with-reason` 口径 | 失败被静默吞掉或直接报错终止，闭环断裂 |
| 写回规则 | 本轮学到的可复用事实写回哪个文件、写什么格式、什么情况不写 | 经验丢失，同类失败重复发生 |

## 2. Case Variable Boundary

**Case Variable Boundary：所有只对本次运行成立的具体值都是案例变量，默认写成变量名，不得写进规则句。**

必须变量化的对象：

| 类别 | 变量名（固定） | 说明 |
| --- | --- | --- |
| 目标角色 | `target roles` | 报告写给谁看（如"采购负责人""带教老师"），写变量，不写具体岗位名 |
| 利益相关方 | `stakeholder` | 谁会基于报告做决策；`stakeholder_view` 为其视角 |
| 公司名 | 一律变量 | 任何真实公司名不得作为规则主语 |
| 行业名 | `research_domain` | 任何具体行业不得出现在规则句中 |
| 受众 | `audience` | 阅读者的知识水平与关注点 |
| 交付目标 | `deliverable_target` | 本轮交付物形态与用途 |
| 一次性验收短语 | 如"老板下周汇报""通过某次评审" | 只属于本轮，禁止成为门禁条件或判据 |

允许写具体值的三个例外（必须写明理由，理由字段为 `case_reason`）：

1. **工具真名**：`tvly`、`mcp__metaso__metaso_web_search` 等是可执行标识，不可变量化——变量化会导致调用失败。理由写明"可执行标识"。
2. **平台约束**：如"微信公众号需用秘塔搜索限定 `site:mp.weixin.qq.com`"——这是客观渠道特性，不是案例。理由写明"渠道客观特性"。
3. **worked example**：示例中的具体行业/公司，必须显式标注为示例（`—— 以下为示例，不进入规则`），且不得出现在任何判据、门禁、默认值中。

自检规则：**把 `research_domain`、`audience`、`target roles` 全部替换成 `XXX` 后，规则句仍然成立** → 合格；若替换后句子读不通或结论变化 → 说明写死了案例，必须重写。

## 3. Stage Contract（四段契约）

每个阶段必须完整写四段。四段缺一不可，缺段即该阶段的产物判定为"未完成"。

### 3.1 Critical Thinking

| 项 | 内容 |
| --- | --- |
| 输入 | 上一阶段的产物 + 用户原话 + `Domain Research Brief` |
| 动作 | 列出本阶段要回答的问题清单；对每个问题写出"可能的答案方向"与"需要什么证据才能判定"；标出最可能出错的地方 |
| 输出 | `question_list[]`（含 each 的 `evidence_needed`、`falsifier`） |
| 通过判据 | 每个问题都有可判定的 `evidence_needed`；至少列出 1 条 `falsifier`（什么证据会推翻当前倾向） |
| 失败条件 | 问题无法判定 / 只写结论方向不写证据需求 / 无 falsifier |

### 3.2 Fetch

| 项 | 内容 |
| --- | --- |
| 输入 | `question_list[]` + 三级搜索协同分工表 |
| 动作 | 一级广度发现（`tvly` 全球域 + 秘塔中文域）→ 二级深度核对（`mcp__metaso__metaso_web_reader` / `tvly extract`）→ 三级缺口补充（微信公众号：秘塔搜索限定 `site:mp.weixin.qq.com`，再 web_reader 取全文） |
| 输出 | 证据库 v1.0（EV-001…，含原文片段与原始链接）+ 一级候选来源清单 |
| 通过判据 | 每条 EV 通过 `Online evidence read` 四项判定（链接可访问 / 有原文片段 / 有可归因主体 / 有时间戳）；每个 `question_list` 条目 ≥ 2 条独立来源，或已记入缺口 |
| 失败条件 | 用搜索摘要充当原文 / 无链接 / 无时间戳 / 抄袭式转述 / 触达成本上限后不记录缺口 |

### 3.3 Deep Thinking

| 项 | 内容 |
| --- | --- |
| 输入 | 证据库 v1.0 |
| 动作 | 归类（共识结论 / 争议观点 / 案例 / 数据）；交叉验证；找反证；构建认知地图（主题 → 子问题 → 结论 → 证据 ID） |
| 输出 | 认知地图 v1.0 + 证据库 v2.0（补入反证与缺口补全证据）+ `conclusions[]` |
| 通过判据 | 核心结论 ≥ 2 个独立来源；争议点正反证据并列；每条结论绑定证据 ID；无证据的结论标 `research-needed` |
| 失败条件 | 单来源当共识 / 只找支持证据 / 结论与证据 ID 脱钩 / 把 `metaso_chat` 输出当证据 |

### 3.4 Review

| 项 | 内容 |
| --- | --- |
| 输入 | 认知地图 + 证据库 + 待输出草稿 |
| 动作 | 逐条跑 Acceptance Matrix；核对双格式一致性；核对关键缺口是否已补搜 |
| 输出 | 验收记录（门禁 / 通过与否 / 证据）+ 未通过项与回退阶段 |
| 通过判据 | Acceptance Matrix 全绿；任一红项必须有明确回退阶段与重跑范围 |
| 失败条件 | 自评通过但无可指认证据 / 红项被忽略 / 双交付物未做一致性核对 |

## 4. 阶段推进与回退规则

```
阶段0 → 阶段1 → 阶段2 → 阶段3（含回退）→ 阶段4 → 阶段5
                   ↑______|（缺口未补 / 反证推翻了认知地图）
```

- 阶段 2 → 阶段 3 的回退触发：出现与 `conclusions[]` 冲突的反证，或证据库 v2.0 中某条核心结论的独立来源降至 1 条。
- 阶段 4 → 阶段 3 的回退触发：Review 发现无证据 ID 的结论、争议点缺一侧、关键缺口未补搜。
- 回退必须写明回退范围（回退到哪个阶段、重跑哪些问题），禁止"整体重来"式回退造成成本失控。

## 5. Critical Thinking / Fetch / Deep Thinking / Review 与阶段映射

四段契约不是四个独立步骤，而是**每个阶段内部的四个动作面**。映射关系：

| 阶段 | Critical Thinking 重点 | Fetch 重点 | Deep Thinking 重点 | Review 重点 |
| --- | --- | --- | --- | --- |
| 阶段0 研究初始化 | 意图转述是否走样 | 不联网（只做本地能力盘点） | 边界与产出目标是否互斥 | `Domain Research Brief` 字段齐全 |
| 阶段1 广度候选 | 检索词覆盖面 | 一级广度发现 | 候选来源去重与初步分级 | 候选清单是否覆盖全部未知项 |
| 阶段2 深度提取 | 每个结论的 falsifier | 二级深度核对 | 认知地图构建 | EV 字段完整性 |
| 阶段3 反证验证 | 反证假设清单 | 三级缺口补充 | 认知地图修订 | 争议点正反并列 |
| 阶段4 信息取舍与输出 | 取舍口径是否对 `audience` 负责 | 不新增检索（除非回退） | 结论—结构—图表链 | 双格式一致性 |
| 阶段5 归档溯源 | 归档是否足以复现 | 不新增检索 | 复用 key 提炼 | 溯源索引完整 |

## 6. Acceptance Matrix

门禁逐条跑，每条必须有可指认的证据。**不通过即阻塞交付**（Hard Stop）。

| 门禁 | 必须通过 | 证据 |
| --- | --- | --- |
| G1 意图对齐 | 报告回答的是 `原始意图` 中的问题，不是相邻问题 | `原始意图` 逐字引用 + 结论到问题的映射表 |
| G2 领域研究先行 | `Domain Research Brief` 齐全且早于阶段 1 | brief 文件 + 首条检索记录的时间先后 |
| G3 证据完整性 | 每条 EV 含全部字段（信息内容 / 类型 / 可信度 / 原文片段 / 来源标题 / 原始链接 / 提取时间 / 检索层级 / 检索工具） | 证据库文件逐条可查 |
| G4 来源合格 | 无"无链接 + 无原文片段"的外部事实 | 抽查记录：随机抽 5 条 EV 打开链接 |
| G5 交叉验证 | 核心结论 ≥ 2 独立来源 | `conclusions[]` 中 `bound_evidence_ids` 长度 ≥ 2 且来源主体不同 |
| G6 争议并列 | 每个争议点正反证据同时出现 | 争议小节 + 正反 EV 编号 |
| G7 缺口补搜 | `research-needed` 项已补搜或已明示披露 | 缺口清单 + 处理记录 |
| G8 双格式一致 | 文档版与 HTML 版内容 100% 一致（措辞、数字、结论、证据编号） | 一致性核对清单（逐条比对结论与数字） |
| G9 HTML 证据绑定 | HTML 中无"无证据 ID 的结论"；证据标签可点击跳转证据库 | HTML 内 `data-ev` 属性扫描结果 |
| G10 交互可用 | HTML 支持按类型与可信度筛选、关键词检索 | 手测记录：筛选与检索各触发一次 |
| G11 成本边界 | 检索次数在预算内；超限情况已记录 | 检索计数（秘塔约 3 积分/次、Tavily 额度） |
| G12 可复现 | 归档包足以让第三方复现结论 | 归档包清单 + 复现步骤 |

## 7. Hard Stops

命中任一条，立即停止当前推进，写清阻塞原因与恢复条件，不得"先交了再说"。

1. 无来源链接 + 原文片段的外部事实 → 禁止写入任何交付物。
2. 核心结论独立来源 < 2 → 禁止标为结论，降级为"待验证判断"或转 `research-needed`。
3. 争议点只写了一方 → 禁止输出该小节。
4. 无证据却写成确定性结论 → 删除该句或补证。
5. 关键缺口未补搜 → 禁止推进阶段 4。
6. HTML 与文档版不一致 → 禁止交付，回退阶段 4。
7. HTML 中出现无证据 ID 的结论 → 禁止交付。
8. `Domain Research Brief` 缺字段或未实测 `Local capability inventory` → 禁止开始阶段 1。
9. 工具真名用错（如 `tavily` 代替 `tvly`）→ 禁止继续，改正后重跑该次调用。
10. 把 `metaso_chat` 的回答直接当证据写入 → 撤销该 EV，重走 `Fetch Before`。
11. 触碰合约外动作（伪造来源、代做发布/付费、替代人工判断下结论）→ 拒绝并说明边界。
12. 触发边界与 `tavily-research` 重叠时未做路由判定 → 先路由，再执行。

## 8. 失败处理

失败分类与处理动作：

| 失败类别 | 判定 | 处理 |
| --- | --- | --- |
| `retryable` | 网络超时、临时 5xx、工具单次失败 | 换一次检索词或工具后重试；同一动作最多重试 2 次 |
| `downgrade` | 原文不可得（付费墙 / 登录 / 无正文） | 降级为二手来源并标 `可信度=中/待验证`，记入 `不可得路径` |
| `research-needed` | 证据数量不足、口径不明、来源矛盾 | 写缺口记录并停止为该问题写结论 |
| `blocked` | 依赖缺失（工具不可用、材料缺失需用户补） | 停止并向 `stakeholder` 说明所需材料与恢复条件 |
| `contract-violation` | 合约外请求（伪造、代发布、替代判断） | 拒绝该动作，保留原产出，说明边界 |

### 8.1 writeback

**writeback：把本轮可复用的经验写回包内对应文件，而不是留在会话里。** 触发条件与目标：

| 触发 | 写回目标 | 写回内容格式 |
| --- | --- | --- |
| 发现更好的检索词/渠道 | `references/intent-domain-research.md`（三级分工表） | 一行：`场景 → 检索式 → 为什么有效` |
| 发现工具真名或调用方式变化 | `references/intent-domain-research.md`（`Local capability inventory`） | 表格行：字段齐全，`usable` 状态更新 |
| 发现新的失败模式 | `references/creation-rule-standard.md`（Hard Stops 或本表） | 新增编号条目 + 触发条件 + 处理动作 |
| 发现双交付物一致性的新坑 | `references/experience-surface-model.md` | 新增完成判据 |
| 阶段契约某段缺判据导致返工 | 本文件第 3 节对应段 | 补齐通过判据 / 失败条件 |

写回要求：写入**规则层**（判据、字段、停止条件），不写"本轮的感受"；一次写回只处理一个失败模式；写回后同类问题的判定必须变得更明确。

### 8.2 none-with-reason

`writeback` 不是必须动作。当且仅当满足下列全部条件时，允许 `none-with-reason`：

- 本轮失败都是 `retryable` 且未产生新的判定歧义；
- 现有规则已能覆盖该失败（不需新增判据）；
- 没有出现新的工具、渠道、字段需求。

`none-with-reason` 必须写成一行记录，字段：`writeback: none` / `reason`（一句话）/ `evidence`（指向本轮哪个记录说明规则已覆盖）。**禁止空写、禁止只写 `none` 不写 `reason`。**

## 9. 提交流程（写文件的顺序）

1. 先填 `Required Anatomy` 十二字段（草稿级即可）。
2. 跑 `Case Variable Boundary` 替换自检（把行业/受众/角色换成 `XXX`）。
3. 写 `Stage Contract` 四段，每段必须有通过判据与失败条件。
4. 写 `Acceptance Matrix`（门禁必须可指认证据）。
5. 写 `Hard Stops` 与失败处理（含 `writeback` / `none-with-reason`）。
6. 最后交由自动门禁校验：`python scripts/check_meta_skill_package.py .`、`python scripts/check_closed_loop.py .`（脚本由使用者提供，本文件不创建脚本）。
