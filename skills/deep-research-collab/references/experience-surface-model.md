# 体验表面模型（experience-surface-model）
> 本文件防止的失败模式：先定好一个漂亮的模板和图表样式，再去凑证据，导致表面（章节、图表、交互控件）与证据能力脱钩；以及中间产物没有落盘，回退和复现都做不到。

## 1. Artifact Chain

每一步都必须落成**文件**（有路径、有文件名），并在文件头记录输入来源。缺任一步的产物文件，即判定该步未完成，不得进入下一步。

| 步 | 输入 | 产物文件名（模板） | 完成判据 |
| --- | --- | --- | --- |
| A1 研究主题 | 用户原话 + `Domain Research Brief` | `00-research-brief.md` | 第 3 节字段齐全；`原始意图` 为逐字引用；含 `不可得路径` 与成本边界 |
| A2 一级候选来源清单 | A1 + 一级广度检索（`tvly` 全球域 + 秘塔中文域） | `01-candidate-sources.md` | ≥20 条候选（领域确实窄时 ≥12 条并附窄因说明）；每条含标题 / 链接 / 渠道 / 语言 / 命中哪个未知项；含被剔除项与剔除理由 |
| A3 证据库 v1.0 | A2 + 二级深度核对（`mcp__metaso__metaso_web_reader` / `tvly extract`） | `02-evidence-v1.0.md` | 每条 EV **十字段**齐全（见第 4 节）；每条都有原文片段与可访问链接；每个待答问题 ≥ 2 独立来源或记缺口 |
| A4 认知地图 v1.0 | A3 | `03-cognition-map-v1.0.md` | 主题 → 子问题 → 结论 → 证据 ID 的映射完整；每条结论已绑定 EV；`conclusions[]` 含 `type` 与 `confidence` |
| A5 证据库 v2.0 / 认知地图 v2.0 | A3 + A4 + 三级缺口补充（微信公众号：秘塔搜索限定 `site:mp.weixin.qq.com`，再 web_reader 取全文） | `02-evidence-v2.0.md`、`03-cognition-map-v2.0.md` | 反证已入证据库；争议点正反并列；`research-needed` 清单已清空或已明示披露；v2.0 相对 v1.0 有变更说明 |
| A6 文档版报告 | A5 | `report.md` | 结论均绑定证据 ID；每个核心结论 ≥ 2 独立来源；`待补证` 小节与 `research-needed` 一一对应 |
| A7 HTML 交互式报告 | A6 | `report.html`（单文件离线） | 内嵌 SVG 图表 / 思维导图 / 流程图 / 证据链路；结论旁证据标签可点击跳转证据库；支持按类型与可信度筛选、关键词检索；与 A6 内容 100% 一致 |
| A8 归档包 | A1–A7 | `archive/`（含 `manifest` 与溯源索引） | 每份文件有 hash 或大小与生成时间；可凭归档包单独复现结论；`manifest` 列出证据 ID → 来源链接的可点击索引 |

回退规则：若 A5 的反证推翻了 A4 的核心结论，则 A4 → A5 之间必须新增版本号（v1.1 / v1.2），**禁止原地覆盖**——原始版本是复现链条的一部分。

## 2. Surface After Domain Research

**Surface After Domain Research：交付物的表面（章节结构、图表类型、交互控件、版式）必须在领域研究完成之后才确定，不得先定模板再找证据。**

顺序硬约束：

```
A1 研究主题（含 Domain Research Brief）
  → 领域研究产出结论类型分布（共识结论 / 争议观点 / 案例 / 数据 各占比）
  → 才决定表面：
       章节数 = 论证目标数（来自 conclusions[]）
       图表类型 = 结论类型分布（见下表）
       交互控件 = 证据库规模与筛选需求
```

表面决策表（由结论类型反向决定，不由审美决定）：

| 结论类型分布 | 表面选择 | 反例（禁止） |
| --- | --- | --- |
| 争议观点占比高 | 必须渲染正反对置面板 + 可信度筛选控件 | 只画一张趋势图掩盖分歧 |
| 数据类占比高 | 对比表 + 柱状/占比图，单元格挂来源 | 无来源也画量级图 |
| 案例类占比高 | 时间线 / 流程图 + 案例卡片 | 把案例写成普遍规律 |
| 阶段/路径类内容 | 流程图（节点附 EV 标签） | 用文字段落硬描述流程 |
| 分类/概念体系 | 思维导图（分支 ≤ 3 层） | 无层级地堆列表 |

自检：**如果我把 `research_domain` 换掉，表面的选型方法是否仍然成立？** 若答案依赖某个具体行业的习惯版式，说明表面被案例绑定了，必须回到 A1 重做。

## 3. worked example

> —— 以下为示例，`research_domain`、公司名、岗位名仅为示例，不进入任何规则、门禁或默认值。

用户原话（模糊请求）："帮我看看这个赛道，下周要跟团队讲一下。"

| 步 | 实际动作 | 产出文件与关键字段 |
| --- | --- | --- |
| A1 | 写 `00-research-brief.md`：逐字引用原话；转述为"为一次内部汇报建立该赛道的体系化认知，并给出选型建议"；`领域假设` 3 条标 `unverified`；`未知` 列 3 个可检索问题（能力边界 / 合规约束 / 定价结构）；`不可得路径` 记"厂商内部路线图（未公开）→ 替代：公开版本日志，标 可信度=中"；成本边界"秘塔 ≤ 20 次检索" | `00-research-brief.md` |
| A2 | 一级广度：`tvly` 搜英文全球域 4 个检索词；秘塔中文域 3 个检索词；得到 22 条候选，剔除 7 条（同源转载、无日期、内容农场），保留 15 条 | `01-candidate-sources.md` |
| A3 | 二级深读：15 条中 11 条用 web_reader / `tvly extract` 取到正文；生成 EV-001…EV-018；每条含 信息内容 / 类型 / 可信度 / 原文片段 / 来源标题 / 原始链接 / 提取时间 / 检索层级 / 检索工具；"合规约束"问题只有 1 条来源 → 记入缺口 | `02-evidence-v1.0.md` |
| A4 | 构建认知地图：主题 → 3 个子问题 → 7 条结论；每条结论绑定 1–4 个 EV；标出 2 条"倾向性判断"（来源数 1 → 待验证） | `03-cognition-map-v1.0.md` |
| A5 | 三级补搜："合规约束"用秘塔搜索限定 `site:mp.weixin.qq.com`，再 web_reader 取 3 篇全文；取到反证 1 条（推翻 A4 的一条倾向判断），补 EV-019…EV-024；修订为 v2.0，附变更说明；缺口清单清空 | `02-evidence-v2.0.md`、`03-cognition-map-v2.0.md` |
| A6 | 按 `conclusions[]` 定章节：7 条结论 → 5 章（合并同源结论 2 组）；写 `report.md`，每条结论后标 `[EV-00x]`；争议点写成"正反并列"小节 | `report.md` |
| A7 | 单文件离线 HTML：结论类型分布为"数据 3 / 争议 2 / 案例 1 / 共识 1" → 选 柱状图 + 对比表 + 正反对置面板 + 流程图；证据标签 `data-ev="EV-019"` 锚点跳转证据库；加"类型"与"可信度"两个筛选器 + 关键词检索框；逐条比对 `report.md` 数字与措辞 | `report.html` |
| A8 | 归档：`archive/manifest.md` 列 8 个文件 + 生成时间 + 大小；附证据 ID → 链接索引；附复现步骤 | `archive/` |

该示例中的行业、公司、岗位**不是规则**。换一个 `research_domain`、换一个 `audience`，A1–A8 的字段与判据不变。

## 4. 证据库字段（贯穿全链的公共结构）

| 字段名 | 说明 | 示例（示例值） |
| --- | --- | --- |
| `evidence_id` | `EV-001` 起，单调递增，禁止复用 | `EV-019` |
| `info_content` 信息内容 | 这条证据说明了什么，一句话 | "某类工具在离线环境不可用" |
| `type` 类型 | 共识结论 / 争议观点 / 案例 / 数据 | `争议观点` |
| `confidence` 可信度 | 高 / 中 / 待验证 | `中` |
| `quote` 原文片段 | 逐字抄录的原文句子 | "…需要联网才能完成首次激活。" |
| `source_title` 来源标题 | 页面标题 | "某产品使用说明（示例）" |
| `source_url` 原始链接 | 可访问 URL | `https://example.com/doc` |
| `extracted_at` 提取时间 | ISO 8601，含时区 | `2025-01-01T10:00:00+08:00` |
| `search_level` 检索层级 | 一级广度 / 二级深度 / 三级缺口 | `三级缺口` |
| `search_tool` 检索工具 | 工具真名 | `mcp__metaso__metaso_web_reader` |

结论结构（`conclusions[]`）：`claim`、`type`、`confidence`、`bound_evidence_ids`（≥1，核心结论 ≥2 且主体不同）、`counter_evidence_ids`（争议点必填）。

## 5. Local Capability Inventory

字段固定；每次运行前实测填写，不得凭印象。**本机没有的能力不得出现在表面设计中。**

| 字段 | 必须写什么 |
| --- | --- |
| `capability` | 用途，一句话（如"HTML→PDF 归档""中文页深读"） |
| `name` / `version` | 工具真名与版本 |
| `invoke` | 调用方式（命令或工具名） |
| `surface_use` | 支撑哪个表面（图表渲染 / 交互控件 / 归档 / 截图） |
| `limits` | 明确限制（语言、条数、是否需要网络、是否需要登录） |
| `cost` | 成本口径（秘塔：约 3 积分/次检索；Tavily：额度上限） |
| `usable` | 可用 / 部分可用 / 不可用 |
| `fallback` | 不可用时的替代表面（如"无法渲染 → 退化为对比表"） |

分类清单（按需求类型填写）：

| 类别 | 要确认的内容 | 实测参考 |
| --- | --- | --- |
| 渲染器 | 是否能把 HTML 转 PDF / 出图 | Chrome 可用：`C:\Program Files\Google\Chrome\Application\chrome.exe`（可做 HTML→PDF 与截图） |
| 浏览器 | 是否有可用浏览器做打开核验 | 同上 |
| 脚本 | 是否有可用解释器 | `python` 当前不在 PATH（探测结果 NOT FOUND）；如需执行 `python scripts/check_meta_skill_package.py .`、`python scripts/check_closed_loop.py .`，先确认解释器路径或改用 `py -3`，不得因报 not found 就宣称通过 |
| 字体 | 中文字体是否可用于 SVG/PDF 渲染 | 需实测；缺字体时避免把中文烘焙进 SVG 图内，改用 HTML 文本 |
| 网络依赖 | 哪些表面依赖联网 | 交互式 HTML 必须**离线可用**：内嵌 SVG 与 CSS/JS，不引外部 CDN，字体与图标不得走外链 |
| 检索工具 | 一级/二级/三级各自的工具 | `tvly`（可执行文件名是 `tvly`，本机 `tavily-cli 0.1.8`）；`mcp__metaso__metaso_web_search` / `metaso_web_reader` / `metaso_chat` / `metaso_topic_list` / `metaso_topic_search` / `metaso_topic_file_content` |

## 6. 单文件离线 HTML 的完成判据（逐条可测）

| 判据 | 测法 |
| --- | --- |
| 单文件 | 断网后双击仍完整渲染；无外部 `http(s)://` 资源引用 |
| 内嵌图表 | SVG 直接内联在 HTML 中（非外部图片文件） |
| 证据链路 | 每个结论旁有证据标签；标签含 `data-ev="EV-0xx"`；点击滚动/跳转到证据库对应条目 |
| 筛选 | 按 `type` 与 `confidence` 筛选，切换后可见条目数变化正确 |
| 检索 | 关键词输入后，无命中的条目隐藏，命中数正确显示 |
| 一致性 | 与 `report.md` 逐条比对：结论句、数字、证据编号完全一致（100%） |
| 证据绑定 | 扫描 HTML：不存在无 `data-ev` 的结论句（G9 门禁） |
