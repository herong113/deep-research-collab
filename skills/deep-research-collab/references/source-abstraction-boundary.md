# 外部材料的抽象与原创边界（抽象 / 原创边界 / 不得复制）
> 本文件防止的失败模式：把外部报告、竞品页面或他人技能包整体搬运进本包，造成命名、结构、视觉、提示词、示例、话术的同源复制；或者反过来，因为怕抄袭而不敢吸收任何质量原则，导致本包退化成通用套话。

## 0. 适用边界与变量

- 变量：`research_domain`、`audience`、`deliverable_target`、`stakeholder_view`。
- 输入材料可以是：外部行业报告、竞品文档与站点、公开课程大纲、他人的研究类技能包或提示词集合、历史项目交付物。
- 输出只允许一种东西：**质量原则**（判定规则、失败模式、字段设计、停止条件）。其余一律不得复制。

## 1. 抽象（Abstraction）是什么

抽象 = 把"某个具体材料里怎么做的"提炼成"任何 `research_domain` 下都必须满足什么"。它必须剥离三类信息：

1. 剥离案例变量：具体行业、公司、岗位、人名、产品名、数字。
2. 剥离表达形式：句式、段落顺序、标题层级、术语造词。
3. 剥离呈现外壳：配色、版式、图标、交互命名、品牌语气。

抽象后的产物形态只能是：一条可判定的规则（含触发条件与处置动作）、一个字段定义、一个失败模式条目、一条停止条件。凡是无法转成上述四类的，一律丢弃。

### 抽象三问（三问全过才允许写入本包）

| 编号 | 问题 | 通过判据 | 不通过时 |
| --- | --- | --- | --- |
| Q1 | 这条规则防止什么失败？ | 能写出一个具体、可复现、可被证据检出的失败场景 | 丢弃：说不清防护目标的就是装饰 |
| Q2 | 它是否依赖某个案例变量？ | 把案例变量全部替换为 `research_domain` / `audience` / `deliverable_target` / `stakeholder_view` 后仍成立 | 丢弃或降级为该案例的局部备注，不入 references |
| Q3 | 换领域还成立吗？ | 至少能在 2 个无关领域（例：`research_domain=B2B 工业配件` 与 `research_domain=公共政策课题`）下给出同样的判定动作 | 丢弃：领域专用规则不进通用 references |

补充判据：三问全过但已有等价条目的，做**合并**而不是新增；合并后必须保留原有停止条件，防止规则被稀释。

## 2. 原创边界 / 不得复制（Do-Not-Copy List）

以下六类内容**禁止**以任何形式（逐字、近义改写、结构平移、换皮）进入本包：

| 编号 | 禁止项 | 说明 | 合规替代做法 |
| --- | --- | --- | --- |
| D1 | 命名 | 技能名、目录名、文件命名体系、术语造词、缩写 | 用本包自己的命名规则（如 `EV-001`、`F-1`、`nextRunReuseKey`、`00-research-brief.md`） |
| D2 | 页面结构 | 章节顺序、目录骨架、模板分节方式 | 依据本包流程阶段 0-5 自行推导结构 |
| D3 | 视觉系统 | 配色方案、字体、间距、组件样式、图表风格 | 自行定义 `Multimodal Brief Contract` 中的配色与字体变量 |
| D4 | 提示词 | 系统提示、角色设定、指令措辞、评分话术 | 用本包的判定规则与字段名重写为可执行条款 |
| D5 | 示例 | 示例主题、示例数据、示例结论、示例图表 | 自造中性示例，且一律以变量占位（`research_domain=<变量>`） |
| D6 | 商业话术 | 营销口号、卖点表述、价值主张、承诺句式 | 只描述能力与停止条件，不做效果承诺 |

同时禁止：把外部材料当成"权威结论"直接引用为证据（外部材料只用于提炼规则，不进入证据库）；在包内保留外部材料的原始链接清单作为来源页。

## 3. 允许与不允许的吸收对照

| 输入材料中的内容 | 判定 | 处理 |
| --- | --- | --- |
| "结论必须绑定来源" | 允许 | 抽象为规则：`findings[]` 的每条结论必须绑定 ≥2 个独立 `EV` |
| 某报告的目录结构 | 不允许 | 丢弃，按本包阶段重建 |
| "先建模板再找证据会跑偏" | 允许 | 抽象为失败模式 `Surface guessed`，写入评测用例 |
| 某竞品的蓝色主色调与卡片圆角 | 不允许 | 丢弃，配色由本包 `Multimodal Brief Contract` 定义 |
| "关键缺口未补搜不得推进" | 允许 | 抽象为阶段 3 停止条件与门禁项 |
| 他人技能包中的一段角色扮演提示词 | 不允许 | 丢弃；需要同等效果时改写为本包的判定规则表 |
| 某课程的章节标题体系 | 不允许 | 丢弃 |
| "证据分层不得互相替代" | 允许 | 抽象为四层证据结构写入治理文件 |

## 4. 落地流程（每次吸收外部材料时执行）

1. 建立吸收清单：逐条摘出材料中的**做法**（不是措辞），编号 `IN-01`、`IN-02`…，只写在运行记录 `loop-run-record.json` 的 `intent_core.inputs` 中，不落地为独立文件。
2. 对每条 `IN` 跑抽象三问，记录三问结论。
3. 三问全过的，检查是否与现有规则重复：重复则合并，不重复则写入对应 `references/*.md`。
4. 三问未过的，显式写 `丢弃`，并在 `loop_decision` 中计入 `none-with-reason` 的依据。
5. 交付前自检：全文搜索是否存在外部专有名词、外部结构痕迹、外部示例残留；存在即判定不合格，回退重写。

## 5. 原创循环与原创边界的关系

- **原创循环**：抽象 → 判定 → 写回 → 下次运行复用 → 再次抽象。循环的每一圈都必须新增或合并一条可判定规则，否则本圈记为 `none-with-reason`。
- **原创边界**：边界不是"不接触外部材料"，而是"只带走规则，不带走形式"。边界被突破的信号：包内出现无法用三问解释的命名/结构/样式；某条规则只能在该外部案例下成立。
- 边界校验的可执行动作：任取本包 3 条规则，对每条写出"它防止什么失败 / 换 `research_domain` 后是否成立"；写不出的规则必须删除或重写。

## 6. 与其它文件的关系

- 证据的合格线见 `references/evidence.md`；本文件约束的是"规则来源"，不是"事实来源"。
- 运行记录中的 `proposal` / `writeback` / `none-with-reason` / `blocked` 判定见 `references/closed-loop-governance.md`。
- 发布前必须通过"无外部形式复制"门禁，见 `references/release-gate.md` 第十四项。
