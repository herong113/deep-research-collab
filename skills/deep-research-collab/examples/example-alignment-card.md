# 示例：需求对齐卡（填好的 worked example）

> 本文件防止的失败模式：把"对齐"写成聊天里的一问一答，事后无法复查当初到底对齐了什么、哪些是用户确认的、哪些是默认值。

用户原话（与 `examples/example-input.md` 同一委托）：

```text
帮我研究一下 AI 编程助手这个赛道，我想给团队做技术选型前的判断，
每个结论都要有来源，最后给我一份能演示的报告。
```

## 1. 一轮原生选择面（3-5 题，宿主：DSH `ask_user_question`）

问题库来自 `assets/alignment-question-bank.json`。实际提问与用户选择：

| # | 问题 | 选项（实际呈现） | 用户选择 |
|---|---|---|---|
| 1 | 这次研究的决策用途是什么？据此决定检索投入档位。 | A 快扫 / B 标准 / **C 深度（含反证回退与争议并列）** | C 深度 |
| 2 | 你希望拿到什么形态的交付物？ | 文档版 / HTML 演示版 / **双交付（推荐）** / 一页决策简报 | 双交付 |
| 3 | 证据的时间窗取多长？ | 近 6 个月 / **近 18 个月（推荐）** / 近 3 年 / 不限 | 近 18 个月 |
| 4 | 研究范围怎么定？ | **你先给候选框架，我确认（推荐）** / 我直接给必答问题 / 只做我圈定的子问题 | 你先给框架，我确认 |
| 5 | 结论的证据门槛定在哪一档？ | **严格：≥2 独立来源 + 原文片段（推荐）** / 标准 / 宽松 | 严格 |

用户在第 5 题后自由文本补充：「时间窗别写死 3 年，另外'能演示'的意思是会上要投屏，不是给我自己看。」

> 若宿主没有原生选择工具：把这些选项作为编号卡片贴出来，明确写"等你选"，状态记 `unconfirmed` 并**停下**；不得由 agent 代选。

## 2. 填好的 `00-alignment-card.md`

```yaml
状态: aligned
确认时间: 2026-09-16
确认方式: 宿主原生选择面（5 题）+ 1 条自由文本补充

## A. 需求侧
研究主题: "AI 编程助手赛道的采用现状与选型依据"
research_domain: "AI 编程助手（国内为主，兼顾海外；含 IDE 内嵌、终端 Agent、平台化三类形态）"
决策用途: "技术选型前的判断依据（会上投屏演示）"
audience: "团队技术选型会（约 8 人，含工程与采购）"
stakeholder_view: "工程负责人视角（关注落地成本与返工风险）"
deliverable_target: "双交付（文档版 Markdown + 单文件离线 HTML 演示版）"
必答问题:
  - Q1: "这类工具的真实采用率有多高？不同统计口径分别是多少？"
  - Q2: "采购与使用的真实成本结构是什么（席位价之外还有什么）？"
  - Q3: "效率收益与质量风险的证据分别是什么？"
  - Q4: "国内团队的合规与私有化约束会造成什么候选集差异？"
本轮不做: ["代码质量实测", "厂商报价谈判", "厂商未公开的内部渗透率", "付费报告原文的获取"]
时间窗: "近 18 个月"

## B. 研究侧
scope.in: ["公开采用率数据与口径", "工具格局与形态分类", "效率与质量证据", "合规与私有化约束", "成本结构"]
scope.out: ["代码质量实测", "报价谈判", "未公开内部数据"]
指标体系: ["采用率（个人使用/企业部署/企业付费 三口径）", "成本结构", "效率证据", "质量风险", "合规约束"]
证据标准: "严格（每条结论 ≥2 独立来源 + 原文片段 + 可访问链接）"
可接受来源: ["一手开发者调查", "署名行业报道", "研究机构报告（可回溯出处）", "厂商官方文档（须标注自披露）"]
拒收来源: ["聚合站且原始出处不可回溯", "AI 摘要页", "无日期转载"]
深度档位: "C（含反证回退与争议并列）"
成本预算: "秘塔 ≤ 8 次检索（约 24 积分）；Tavily ≤ 5 次"
时间预算: "本轮出初版；深度补搜可在下一轮追加"

## C. 确认记录
用户改动: ["把'能演示'澄清为'会上投屏' → 需要 HTML 交互版而非仅文档", "时间窗不要写成 3 年"]
取默认值的字段: []
未决项: []
```

## 3. 门禁自检（进入阶段 1 之前）

| 检查项 | 结果 |
|---|---|
| 状态 = `aligned` | 通过 |
| `research_domain` / `决策用途` / `必答问题` 均非空 | 通过（必答问题 4 条，≤5） |
| `本轮不做` 非空 | 通过（4 项） |
| 指标体系可核查（不是"市场情况"这类空话） | 通过（5 个指标均可被证据判定） |
| 成本预算已写死 | 通过（秘塔 ≤ 8 次 / Tavily ≤ 5 次） |
| 是否有字段靠猜 | 无（无默认值） |

## 4. 如果跳过这一步会怎样（反例）

- 不问深度档位 → 按"快扫"跑完才发现用户要的是会上决策，反证与争议全缺，等于重做。
- 不问交付形态 → 只出 Markdown，用户要投屏时只能临时补做 HTML。
- 不问本轮不做 → 范围膨胀到"顺便把代码质量也测一下"，预算翻倍且交付延期。
- 让 agent 代选"受众" → 事后无法判断报告深浅是否与读者匹配，验收失去判据。
