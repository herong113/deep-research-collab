# 证据库工作模板（evidence-library）
> 本文件防止的失败模式：证据散落在对话里、编号重排、可信度凭感觉标、交叉验证数量说不清，导致报告里的 `[EV-00X]` 无法回溯，或把单一来源的孤证当成行业共识。

用途：从**阶段 2 深度提取与认知地图**开始逐条登记，贯穿阶段 3–5；报告定稿时本表随交付物归档。

---

## 1. 证据字段说明

| 字段 | 是否必填 | 填写说明 | 允许值 / 格式 |
|---|---|---|---|
| 证据 ID | 必填 | 全局唯一编号 | `EV-001` 起，三位数字，不复用 |
| 信息内容 | 必填 | 这条证据说了什么，用一句可独立读懂的话 | 自由文本，≤80 字 |
| 类型 | 必填 | 证据性质 | 共识结论 / 争议观点 / 案例 / 数据 |
| 可信度 | 必填 | 按第 3 节口径判定 | 高 / 中 / 待验证 |
| 原文片段 | 必填 | 从来源逐字摘录的支撑句（不得改写、不得拼接） | 原文语言，加引号 |
| 来源标题 | 必填 | 来源的标题 | 自由文本 |
| 原始链接 | 必填 | 可点击的原始 URL；失效要标注 | 以 `http` 开头 |
| 提取时间 | 必填 | 实际提取日期 | `YYYY-MM-DD` |
| 检索层级 | 必填 | 这条证据来自哪一级搜索 | 一级 / 二级 / 三级 |
| 检索工具 | 必填 | 实际调用的工具真名 | 见下方工具真名表 |
| 交叉验证数 | 必填 | 支持同一信息内容的**独立来源**数量（含本条） | 整数 ≥1 |
| 可信度判据 | 必填 | 一句话写明为什么给这个可信度 | 自由文本 |

**检索层级与工具真名对照**（工具名必须写全名，不得简写或臆造）：

| 检索层级 | 定位 | 允许的检索工具真名 |
|---|---|---|
| 一级 | 广度发现：全球域 + 中文域 | `tvly search`（Tavily CLI，可执行文件名 `tvly`，不是 `tavily`）、`mcp__metaso__metaso_web_search` |
| 二级 | 深度核对：取原文核对 | `mcp__metaso__metaso_web_reader`、`tvly extract` |
| 三级 | 缺口补充：中文一手实践材料 | 秘塔搜索限定 `site:mp.weixin.qq.com` + `mcp__metaso__metaso_web_reader` 取全文 |

辅助工具（不作为主证据来源，但可在备注中记录）：`mcp__metaso__metaso_chat`、`mcp__metaso__metaso_topic_list`、`mcp__metaso__metaso_topic_search`、`mcp__metaso__metaso_topic_file_content`。

**成本备注**：秘塔每次检索约 3 积分；Tavily 有额度上限。逐条登记时在批次汇总里记消耗。

## 2. EV 编号规则

1. 编号格式固定为 `EV-` + 三位数字：`EV-001`、`EV-002`……`EV-999`；超过 999 用 `EV-1000` 继续递增，仍保持 `EV-` 前缀。
2. **编号只增不改**：一旦分配，编号永久绑定该条证据；修改内容保留编号，但在备注记录修改时间。
3. **禁止复用**：被删除的证据编号作废，不重新分配给别的证据（可在备注写"已作废"）。
4. **禁止重排**：不得为了"好看"重新编号；报告、payload、HTML 中的引用必须与本表逐字一致。
5. 分配顺序 = 登记顺序，与检索层级无关；同一批检索产出的证据连续编号便于追溯。
6. 报告中的引用写法统一为 `[EV-001]`；一次引用多条写 `[EV-001][EV-004]`。
7. 每条核心研究发现至少挂 1 个 EV；争议观点必须正反各挂至少 1 个 EV。
8. 编号查重是交付前的必做校验（见第 6 节）。

## 3. 可信度判定口径

判定顺序：**先看来源属性 → 再看是否有原文片段 → 再看交叉验证数 → 最后看时效**。任一步不满足则不得升格。

### 高

同时满足以下全部条件：
- 来源为一手或准一手：官方公告/原文、监管文件、上市公司年报与财报、权威统计机构数据、原始论文、当事方公开声明；
- 有逐字原文片段可直接支撑结论（不是转述、不是标题党摘要）；
- 原始链接可访问，且内容与原文片段一致；
- 交叉验证数 ≥2（独立性要求：不同机构/不同作者/不同渠道，转载不算独立）；
- 数据在有效期内（例如年度数据不超过 2 年，快照类数据标注提取日）。

### 中

满足以下任一情形且不存在硬伤：
- 来源为二手但可信（行业媒体、研究机构综述、行业协会报告、资深从业者署名文章）；
- 或来源虽为一手，但交叉验证数 = 1；
- 或原文片段只能间接支撑（需要一步推理才能得到结论）；
- 或数据偏旧但仍具参考意义（已标注时效）。
- **禁止**：把"看起来专业"当成高可信度的依据；中就是中，不得因为结论符合预期而升格。

### 待验证

出现以下任一情形即判为待验证：
- 只有单一来源且来源属性不明（自媒体、匿名帖、无署名转述）；
- 与已有证据存在冲突且未能解释；
- 找不到原文片段，只有摘要或二手转述；
- 链接失效且无可替代来源；
- 数字口径不清（不知统计范围、时点、样本）；
- 来源本身带有明确商业立场且无第三方独立印证。
- **待验证结论可以写进报告，但必须显式标注，且不得进入"核心结论摘要"当作既定事实。**

### 交叉验证数的作用

| 交叉验证数 | 最低可信度上限 | 说明 |
|---|---|---|
| 1 | 中（来源不明则为待验证） | 孤证不得判高 |
| 2 | 高（且其余条件满足） | 两个独立来源 |
| ≥3 | 高 | 独立来源≥3，可支撑"共识结论"类型 |

**独立性判定**：同源转载、同一机构多篇稿件、互相引用的文章，均计为 1 个来源。

## 6. 交付前校验

| 校验项 | 动作 | 通过判据 |
|---|---|---|
| 编号唯一 | 对证据 ID 列查重 | 无重复编号 |
| 编号连续可读 | 检查缺失与作废标记 | 缺口均有"已作废"说明 |
| 字段齐全 | 逐行检查 12 列是否为空 | 无空必填项 |
| 枚举合法 | 检查类型/可信度/检索层级取值 | 全部落在允许集合 |
| 工具真名 | 检查工具列 | 只出现第 1 节列出的真名；CLI 写 `tvly` |
| 引用一致 | 报告与 payload 中的 `[EV-00X]` 是否都在本表 | 无悬空编号 |
| 反向一致 | 本表每条 EV 是否被引用（或标注"备查"） | 无遗漏或已说明 |
| 孤证检查 | 交叉验证数 = 1 的条目 | 可信度不得为高 |
| 链接可达 | 抽检 ≥30% 链接 | 可达或已标注失效 |
| 示例残留 | 扫描是否还有 `https://example.com/` | 正式交付中无示例数据 |
