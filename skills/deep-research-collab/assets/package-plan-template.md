# 包计划模板（package-plan）
> 本文件防止的失败模式：为了"看起来完整"往技能包里堆文件，导致包内每个文件没有对应失败模式、没有验证方式、没人知道该不该删——包越写越重但实际更容易跑偏。

用途：编辑技能包之前先填这张表。填写规则——**每个文件必须先写出它防止的具体失败模式，再写出由哪个校验命令或产物证明它有用；写不出来的文件不进包。**

变量说明：`research_domain` = 研究领域；`deliverable_target` = 交付目标。

## 3. 证据（每个承诺由什么证明）

| 承诺 | 证明层级 | 具体证据形态 | 谁来采集 | 采集时点 |
|---|---|---|---|---|
| 触发边界正确 | 运行证据 | 触发/不触发对照记录 | 包作者 | 每次改触发表述后 |
| 阶段流程可执行 | 运行证据 | 一次完整跑通的阶段流转记录 | 执行者 | 首次跑通时 |
| 证据可溯源 | 产物证据 | 报告 + 证据库交叉核对表 | 执行者 | 每次交付前 |
| 双格式一致 | 产物证据 | 逐模块一致性核对表 | 执行者 | 每次交付前 |
| 结构合法 | 结构证据 | 校验脚本/结构检查输出 | 包作者 | 发布前 |
| 离线 HTML 可用 | 产物证据 | 断网打开 + 交互可用的观察记录 | 执行者 | 发布前 |
| 成本可控 | 运行证据 | 消耗记录（次数/积分） | 执行者 | 每轮结束 |
| 闭环成立 | 运行证据 | 运行记录 + 写回决策 | 执行者 | 每轮结束 |

证明层级只允许：结构证据 / 产物证据 / 运行证据 / 人工确认。**低层通过不能替代高层**（例如结构校验通过 ≠ 报告内容可信）。

## 4. 校验（命令与产物对照）

| 校验 ID | 校验目标 | 校验方式（命令或动作） | 期望输出 | 失败时怎么办 |
|---|---|---|---|---|
| V-1 | 包结构完整 | 结构检查：入口、参考、资产、评测目录与文件齐全 | 无缺失项 | 补齐或从计划中删除该项 |
| V-2 | 模板可填写 | 按模板填一份最小样例 | 所有字段可填、无死字段 | 修订模板字段 |
| V-3 | JSON 结构合法 | 用 `json.load` 解析 `report-payload-template.json` | 解析成功、无异常 | 修复 JSON 语法 |
| V-4 | 枚举值合法 | 检查 `type` / `credibility` / `layer` / `kind` / 案例 `type` | 全部落在允许集合内 | 修改取值 |
| V-5 | 证据编号唯一 | 证据库内 EV 编号查重 | 无重复、编号连续可读 | 重新编号并同步引用 |
| V-6 | 双格式一致 | 逐模块比对 Markdown 与 HTML 文本 | 内容无差异 | 从同一 payload 重新渲染 |
| V-7 | 溯源可达 | 抽检 ≥N 条链接 | 链接可访问或已标注失效 | 标注失效并降级可信度 |
| V-8 | 闭环有决策 | 检查运行记录决策字段 | ∈ {writeback, proposal, none-with-reason, blocked} | 补齐决策与理由 |
| V-9 | 禁用表述扫描 | 扫描交付文本中的越界表述与外部项目文案 | 无命中 | 改写为本包自有表述 |

**填写要求**：每个校验 ID 必须写"期望输出"，只写"检查一下"不算校验。
