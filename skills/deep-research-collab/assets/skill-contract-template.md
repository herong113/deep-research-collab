# 技能契约模板（skill-contract）
> 本文件防止的失败模式：触发边界含糊导致该用的时候不触发、不该用的时候乱触发；以及研究范围、评测口径、交付边界三件事没有事先写死，事后无法验收。

变量说明：`research_domain` = 研究领域；`audience` = 报告读者；`deliverable_target` = 交付目标；`stakeholder_view` = 关键干系人视角。

---

## 1. Should Trigger（应该触发）

| 编号 | 触发表述（用户可能怎么说） | 触发理由 | 第一动作 |
|---|---|---|---|
| T-1 | "帮我系统研究一下 `{research_domain}`" | 陌生领域体系化研究 | 进入阶段 0，先出研究简报 |
| T-2 | "做一份行业深度调研" | 行业深度调研 | 先界定范围与读者，再开搜 |
| T-3 | "这个内容/课程/产品能不能做，先论证一下" | 前期论证 | 明确决策用途与成败判据 |
| T-4 | "帮我做课题研究 / 文献级梳理" | 课题研究 | 明确证据类型偏好与引用规范 |
| T-5 | "要能溯源、每条结论都要有来源" | 证据导向要求 | 启用证据模型与溯源备案 |
| T-6 | "给我 Markdown + 一个能点开的离线网页" | 双格式交付要求 | 进入阶段 4 双格式输出 |

- 触发词与"证据、溯源、反证、缺口、双格式交付"共现时，优先级提高。
- 触发不要求用户说出技能名，只要求任务形态匹配。

## 2. Should Not Trigger（不应触发）

| 编号 | 用户表述 | 为什么不触发 | 正确路由 |
|---|---|---|---|
| N-1 | "查一下今天天气 / 某公司电话" | 单点事实查询，无需体系化 | 直接单次检索回答 |
| N-2 | "把这段文字翻译一下" | 无研究成分 | 普通文本处理 |
| N-3 | "这条新闻讲了什么" | 单源摘要 | 单次读取即可 |
| N-4 | "帮我写一篇公众号长文" | 写作交付，非调研交付 | 交给写作类技能/流程 |
| N-5 | "优化一下这段代码" | 无关领域 | 工程类流程 |
| N-6 | "总结一下我刚给你的这份 PDF" | 已给定单一材料 | 直接阅读总结，无需三级搜索 |

## 3. Near-Miss（近似但不触发 / 触发但需降级）

| 编号 | 近似场景 | 判定 | 处理 |
|---|---|---|---|
| M-1 | "快速了解一下 `{research_domain}`，5 分钟就行" | 触发但降级 | 只跑阶段 0/1/4，明确标注"未做反证验证" |
| M-2 | "我只要一份资料清单，不要报告" | 触发但降级 | 输出阶段 1/2 的候选池与证据库，不出完整报告 |
| M-3 | "对比 A 和 B 两个产品" | 触发（限定范围） | 按对比型研究跑，范围 `scope.in` 写清对比维度 |
| M-4 | "帮我判断这条结论真假" | 触发（局部） | 只跑阶段 3 反证验证，不展开三级搜索全流程 |
| M-5 | "研究一下，顺便写成 PPT" | 触发 + 扩展交付 | 主交付仍是双格式，PPT 作为附带产物并标注非技能保证项 |
| M-6 | "已经有报告了，帮我看看证据够不够" | 触发（评审模式） | 只跑证据充分度评级与缺口补全 |

## 4. Ambiguous Handling（模糊输入处理）

| 模糊点 | 默认假设（不阻塞可继续） | 必须澄清（阻塞，先问再跑） | 澄清问法 |
|---|---|---|---|
| 读者是谁 | 默认 `audience` = 决策者 | 用途是内部决策还是对外发布 | "这份报告主要给谁看？" |
| 范围边界 | 默认纳入近 3 年、公开可检索材料 | 是否含付费库/内部材料/非公开数据 | "有没有必须纳入或必须排除的来源？" |
| 深度 | 默认"重要结论必须有反证" | 是否接受"待验证"结论进入正式报告 | "拿不准的结论是标注待验证，还是必须先补证？" |
| 时间 | 默认以最近可得信息为准 | 是否有明确数据截止日 | "数据截止到什么时候？" |
| 交付 | 默认双格式（Markdown + 单文件离线 HTML） | 是否只要其中一版 | "两版都要，还是只要其中一版？" |
| 成本 | 默认单轮预算内完成 | 是否允许为补缺口追加检索预算 | "为补一个缺口最多允许多花几次检索？" |

**模糊处理规则**：
1. 一次最多向用户提 ≤3 个澄清问题，且必须是"问了会改变研究路线"的问题。
2. 不影响路线的模糊点直接按默认假设继续，并在报告"附录—异常处理"里记录假设。
3. 澄清通过宿主原生提问工具进行；Markdown 选择卡只能作为降级等待界面，不得当作已确认。

## 5. Domain Research Contract（领域研究契约）

| 契约项 | 约定内容 |
|---|---|
| 研究领域 | `{research_domain}` |
| 读者与用途 | `{audience}` / `{deliverable_target}` |
| 干系人视角 | `{stakeholder_view}`（报告需回答该视角最关心的 1–2 个问题） |
| 范围纳入 | `scope.in`：{纳入范围} |
| 范围排除 | `scope.out`：{排除范围} |
| 证据模型 | 证据 ID（EV-001…），字段 = 信息内容、类型（共识结论/争议观点/案例/数据）、可信度（高/中/待验证）、原文片段、来源标题、原始链接、提取时间、检索层级、检索工具 |
| 三级搜索协同 | 一级广度发现（`tvly` 全球域 + `mcp__metaso__metaso_web_search` 中文域）；二级深度核对（`mcp__metaso__metaso_web_reader`、`tvly extract`）；三级缺口补充（微信公众号：秘塔搜索限定 `site:mp.weixin.qq.com` + `metaso_web_reader` 取全文） |
| 必须出现的模块 | 报告概览（含证据充分度评级）、领域认知地图、三级搜索来源溯源、核心研究发现、争议与反证分析、典型案例库、完整证据库、附录 |
| 交付物 | ①文档版研究报告（Markdown）②单文件离线 HTML 交互式报告；两版内容 100% 一致 |
| 成本边界 | 秘塔每次检索约 3 积分；Tavily 有额度上限；超出预算前需回报 |
| 禁止事项 | 无来源结论、伪造证据 ID、伪造链接、把"未检索到"写成"不存在"、单方面修改一版交付物 |

## 6. Eval Contract（评测契约）

| 评测项 | 检查什么 | 通过判据 | 证据形态 |
|---|---|---|---|
| 触发评测 | T-1…T-6 是否触发 | 命中率达标且无误触发 N-1…N-6 | 触发对照记录 |
| 边界评测 | M-1…M-6 是否正确降级 | 每个 near-miss 有明确判定与降级说明 | 判定记录 |
| 证据完整性 | 每条结论是否带 `[EV-00X]` | 核心研究发现 100% 带编号；编号在证据库中存在 | 报告 + 证据库交叉核对 |
| 溯源可达性 | 每个 EV 是否有可点原始链接 | 链接非空且非伪造；失效者有失效标注 | 链接清单抽检 |
| 反证到位 | 关键结论是否有反证或明确"未找到反证" | 争议模块正反并列，反证有 EV 编号 | 争议表 |
| 双格式一致 | Markdown 与 HTML 内容是否一致 | 逐模块比对无差异（允许版式差异） | 一致性核对表 |
| 证据充分度 | 是否给出评级与理由 | 评级 ∈ {充分, 基本充分, 不足} 且有理由 | 报告概览 |
| 成本合规 | 是否超预算 | 未超，或超预算前已回报并获得同意 | 消耗记录 |

**不达标处理**：任一评测项不通过 → 回到对应阶段修复，不允许"带病交付"；无法修复时在报告与回报中显式写明未达标项。

## 7. Boundary Contract（交付边界契约）

| 边界项 | 承诺 | 不承诺 |
|---|---|---|
| 信息覆盖 | 在 `scope.in` 范围内做到可解释的覆盖 | 绝对穷尽、内部非公开数据 |
| 结论时效 | 标注提取时间与数据截止日 | 对提取日之后的变化负责 |
| 可信度 | 三级可信度判定口径公开 | 保证"高可信度"等于事实正确 |
| 工具可用性 | 记录实际使用的检索层级与工具 | 跨环境工具必然可用 |
| 离线报告 | 单文件、断网可打开、可交互 | 对外部服务、外链资源的可用性负责 |
| 内容一致性 | 两版内容 100% 一致 | 两版版式、交互细节一致 |
| 成本 | 预算内完成或提前回报 | 无限次检索 |

**边界声明必须出现在报告"附录—归档信息"中**，供读者判断适用性。
