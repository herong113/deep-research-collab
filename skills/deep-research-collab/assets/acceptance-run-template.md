# 验收运行记录模板（acceptance-run）
> 本文件防止的失败模式：口头声称"跑通了、可以交付了"，但拿不出这次运行实际读了什么、跑了什么校验、哪些层面通过、哪些只是人眼觉得还行——把结构检查的通过当成内容可信的通过。

用途：每次发布、交付或迁移 `deep-research-collab` 之前填写一份，一次运行一行记录。

变量说明：`research_domain` = 研究领域；`audience` = 报告读者；`deliverable_target` = 交付目标；`stakeholder_view` = 关键干系人视角。

---

## 1. 运行类型

| 字段 | 填写说明 | 本次填写 |
|---|---|---|
| 运行 ID | 形如 `RUN-{YYYYMMDD}-{序号}` | RUN-{YYYYMMDD}-01 |
| 运行类型 | 首次跑通 / 回归运行 / 边界运行 / 受阻塞运行 / 发布前验收 | {类型} |
| 触发原因 | 为什么现在跑这次 | {原因} |
| 运行范围 | 覆盖哪些阶段 | 阶段 {0–5} |
| 输入 | `research_domain` = {领域}；`audience` = {读者}；`deliverable_target` = {目标}；`stakeholder_view` = {视角} | {填写} |
| 不做的事 | 本次明确不覆盖的部分 | {非目标} |
| 成本预算 | 秘塔约 3 积分/次、Tavily 有额度上限 | 秘塔 ≤ {N} 次；Tavily ≤ {N} 次 |
| 执行环境 | 宿主/系统/可用工具 | {环境描述} |

## 2. 读取边界

明确本次运行**实际读取了什么、没有读取什么**，防止"以为读了"。

| 类别 | 本次读取 | 本次未读取（并说明原因） |
|---|---|---|
| 技能包文件 | 例如 `SKILL.md`、`assets/document-report-template.md` | 例如 `evals/`（本次不跑评测） |
| 用户材料 | {文件/链接} | {未读原因} |
| 一级来源 | `tvly` 全球域检索 {N} 条；`mcp__metaso__metaso_web_search` 中文域 {N} 条 | {未覆盖的域} |
| 二级核对 | `mcp__metaso__metaso_web_reader` {N} 篇；`tvly extract` {N} 篇 | {取不到全文的来源及原因} |
| 三级补充 | 微信公众号：秘塔搜索限定 `site:mp.weixin.qq.com` + `metaso_web_reader` 取全文 {N} 篇 | {未补上的缺口} |
| 未使用的可用能力 | 例如 `mcp__metaso__metaso_chat`、`metaso_topic_list`、`metaso_topic_search`、`metaso_topic_file_content` | {为什么没用} |

**边界声明**：本次结论只对"已读取"部分成立；未读取部分不得写进结论，只能写进缺口清单。

## 4. 证据分层

| 层级 | 本次采集到的证据 | 证明了什么 | 不能证明什么 |
|---|---|---|---|
| 结构证据 | {文件清单 / 结构检查输出} | 包结构与字段形态齐全 | 内容是否可信、流程是否跑得通 |
| 产物证据 | {Markdown 报告、离线 HTML、证据库、payload} | 交付物确实生成且形态正确 | 结论是否为真、来源是否支持结论 |
| 运行证据 | {阶段流转记录、工具调用记录、消耗记录、异常记录} | 流程按契约执行、成本可控 | 结论质量高低 |
| 人工确认 | {用户/干系人对范围、读者、结论的确认} | 交付符合 `deliverable_target` 与 `stakeholder_view` 期待 | 不能替代溯源检查 |

**层级规则**：低层通过不能替代高层；结构证据全绿但运行证据缺失时，本次运行**不得判定为通过**。

## 5. 分数与判定

| 维度 | 权重 | 评分口径（0–5） | 得分 | 依据（哪条证据） |
|---|---|---|---|---|
| 流程完整 | 20% | 5=阶段 0–5 全跑通；3=主路径跑通有回退；0=中断 | {分} | {证据 ID} |
| 证据可溯源 | 25% | 5=每条结论可点回原文；3=少量缺失；0=大量无来源 | {分} | {证据 ID} |
| 反证充分 | 20% | 5=关键结论均有反证或"未找到反证"说明；0=只找支持证据 | {分} | {证据 ID} |
| 双格式一致 | 15% | 5=逐模块一致；0=不一致 | {分} | {证据 ID} |
| 离线可用 | 10% | 5=断网可交互；0=打不开 | {分} | {证据 ID} |
| 成本与边界合规 | 10% | 5=预算内且边界外需求已拒/已记录；0=超预算且未回报 | {分} | {证据 ID} |

加权总分 = Σ(得分 × 权重) = **{总分} / 5**

| 判定 | 条件 | 本次判定 |
|---|---|---|
| PASS | 总分 ≥ 4.0，且"证据可溯源""反证充分"均 ≥ 4，且无 C-1/C-4/C-6/C-7 不通过 | ☐ |
| CONDITIONAL | 总分 ≥ 3.2，存在可修复项且已列出修复计划 | ☐ |
| FAIL | 总分 < 3.2，或存在溯源/一致性硬伤 | ☐ |
| BLOCKED | 关键能力不可用（如离线 HTML 无法生成、检索工具不可用），无法判定 | ☐ |
