# 需求对齐卡模板（requirements alignment card）

> 本文件防止的失败模式：一上来就开始搜，做完才发现边界、受众、交付形态、成本预算全对不上——返工的不是报告，是整轮检索。

用途：**阶段 0 的第一个动作**。先和用户对齐这张卡，再写 `Domain Research Brief`，再开检索。卡的产物是 `00-alignment-card.md`，状态必须是 `aligned` / `defaulted` / `unconfirmed` 之一。

---

## 1. 一页卡片（直接复制填写）

```yaml
# 00-alignment-card.md
状态: aligned            # aligned | defaulted | unconfirmed
确认时间: 2026-01-01
确认方式: 宿主原生选择面  # 宿主原生选择面 | 对话选项卡（降级） | 用户逐字回复

## A. 需求侧（必须由用户确认或显式取默认）
研究主题: "<一句话>"
research_domain: "<领域边界，含地域与细分>"
决策用途: "<这份研究支撑什么决定>"
audience: "<报告读者>"
stakeholder_view: "<关键干系人视角>"
deliverable_target: "<归档 / 演示 / 决策简报 / 双交付>"
必答问题:                          # 3-5 个，按优先级排序
  - Q1: "<必须被回答的问题>"
  - Q2: "<...>"
本轮不做:                          # 明确排除，防止任务膨胀
  - "<不做的事 1>"
时间窗: "<近 6 个月 / 近 18 个月 / 近 3 年 / 不限>"

## B. 研究侧（由研究方提出，用户可改）
scope.in: ["<纳入范围>"]
scope.out: ["<排除范围>"]
指标体系: ["<可核查指标 1>", "<指标 2>", "<指标 3>"]   # 3-6 个，每个都要能被证据判定
证据标准: 每条结论≥2 独立来源 + 原文片段 + 可访问链接   # 严格 | 标准 | 宽松
可接受来源: ["一手研究", "署名报道", "官方文档"]
拒收来源: ["聚合站无原始出处", "AI 摘要页", "无日期转载"]
深度档位: B                       # A 快扫 | B 标准 | C 深度
成本预算: 秘塔 ≤ 4 次检索（约 12 积分）；Tavily ≤ 3 次
时间预算: "<本轮内出初版 / 可分两轮>"

## C. 确认记录
用户改动: ["把时间窗从 3 年改成 18 个月"]
取默认值的字段: ["audience 未指定 → 记为 unspecified，在报告首屏声明限制"]
未决项: []
```

**填写规则**

1. **不许填空**：任何字段拿不到用户输入时，只能走第 3 节的默认值表，并写进 `取默认值的字段`；禁止自己"合理地猜一个"然后当成用户确认。
2. **必答问题 ≤ 5 个**：超过 5 个说明研究边界还没收敛，先砍范围而不是加问题。
3. **`本轮不做` 必须非空**：一个都不写的请求几乎必然膨胀。
4. **指标体系必须可核查**：写"市场情况"不合格，写"采用率（三口径）/ 定价结构 / 监管约束"合格。
5. **成本预算先写死**：秘塔每次检索约 3 积分、Tavily 有额度上限；超预算必须先回报，不得静默超额。

## 2. 和用户对齐的方式（宿主原生选择面优先）

一轮问 **3-5 题**，每题 **2-4 个选项**，每个选项写清后果；最后一题允许自由文本补充。问题库见 `assets/alignment-question-bank.json`（含每题默认值与跳过条件）。

| 运行宿主 | 用什么问 |
| --- | --- |
| DSH | `ask_user_question`（questions 数组） |
| Codex | `request_user_input` |
| Claude Code | `AskUserQuestion` |
| 都没有 | 降级：在对话里列出编号选项，明确写"等你选"，然后**停下** |

**降级不等于可以替用户选**：没有原生选择工具时，Markdown 选择卡只是等待界面，状态写 `unconfirmed`，不得继续进入阶段 1。

**必须问的五件事**（其余字段由研究方拟定后请用户确认）：

1. **决策用途 + 深度档位**：A 快扫（1 轮检索，只要轮廓）/ B 标准（三级搜索 + 证据库）/ C 深度（含反证回退与争议并列）。
2. **交付物形态**：文档版 / HTML 演示版 / 双交付 / 一页决策简报。
3. **时间窗**：近 6 个月 / 近 18 个月 / 近 3 年 / 不限。
4. **范围收敛方式**：用户给必答问题 / 研究方先给候选框架再确认 / 只做用户圈定的子问题。
5. **证据标准**：严格（每条结论 ≥2 独立来源 + 原文片段）/ 标准 / 宽松（允许单一权威来源，须标注）。

推荐默认（用户说"你定"时使用）：**B 标准档 + 双交付 + 近 18 个月 + 研究方先给候选框架 + 严格证据标准**。

## 3. 用户不回答时的默认值表

| 字段 | 默认值 | 后果与声明义务 |
| --- | --- | --- |
| `audience` | `unspecified` | 报告首屏声明"受众未指定，按通用读者撰写" |
| `stakeholder_view` | `general` | 决策类结论只给条件与证据，不给单一推荐 |
| `deliverable_target` | 双交付（文档版 + HTML） | 无 |
| `时间窗` | 近 18 个月 | 报告标注时间窗，超窗数据标注并降级 |
| `深度档位` | B 标准 | 无 |
| `证据标准` | 严格 | 达不到就写缺口，不得降格 |
| `成本预算` | 秘塔 ≤ 4 次 + Tavily ≤ 3 次 | 触顶必须先回报再继续 |

取默认后状态记 `defaulted`，并在报告首屏与运行记录的 `Intent Core` 段各写一句。

## 4. 确认门禁（硬停止）

- 卡片状态为 `unconfirmed` → **不得进入阶段 1**，也不得先"顺手搜两条看看"。
- 卡片缺 `research_domain` / `决策用途` / `必答问题` 任一 → 不得进入阶段 1。
- `必答问题` 为空或写成"全面了解该领域" → 视为未对齐，退回重写。
- 用户中途改需求 → 更新卡片、升版本号、标注改动点，并检查已产出的证据是否需要作废（作废的 `EV` 不得进入 v2.0）。

## 5. 示例（`research_domain` 仅作示例，不进入规则）

用户原话："帮我研究一下 AI 编程助手这个赛道，我想给团队做技术选型前的判断，每个结论都要有来源，最后给我一份能演示的报告。"

```yaml
状态: aligned
决策用途: 技术选型前的判断依据
research_domain: AI 编程助手（国内为主，兼顾海外）
audience: 团队技术选型会
stakeholder_view: 工程负责人
deliverable_target: 双交付（文档版 + HTML 演示版）
必答问题:
  - Q1: 这类工具的真实采用率有多高（不同口径分别是多少）？
  - Q2: 采购与使用的真实成本结构是什么？
  - Q3: 效率收益与质量风险的证据分别是什么？
本轮不做: [代码质量实测, 报价谈判, 厂商内部路线图]
时间窗: 近 18 个月
指标体系: [采用率（个人/企业部署/企业付费三口径）, 成本结构, 效率证据, 质量风险, 合规约束]
证据标准: 严格（每条结论 ≥2 独立来源 + 原文片段）
深度档位: C（含反证回退）
成本预算: 秘塔 ≤ 6 次；Tavily ≤ 3 次
用户改动: ["把'研究报告'明确为'能演示'→ 需要 HTML 交互版"]
取默认值的字段: []
```

完整填写示例见 `examples/example-alignment-card.md`。
