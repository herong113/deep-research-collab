# 产品设计看板模板（product-design-board）
> 本文件防止的失败模式：把"跑完了流程"当成"用户拿到了东西"——没有可见结果、没有体验路径、边界写不清、每轮结束后不闭环，导致同样的坑反复踩。

用途：在设计或改版 `deep-research-collab` 的对外表面时填写；在每轮运行结束时更新第 4 节看板。

变量说明：`research_domain` = 研究领域；`audience` = 报告读者；`deliverable_target` = 交付目标；`stakeholder_view` = 关键干系人视角。

---

## 1. 3 分钟可见结果

定义：用户从"给出需求"到"看到第一个有价值的东西"，必须在 3 分钟内发生，且**不依赖完整流程跑完**。

| 时点 | 用户看到什么 | 形态 | 生成成本 | 是否可在 3 分钟内达成 |
|---|---|---|---|---|
| 第 0–1 分钟 | 研究简报草案：意图复述、范围纳入/排除、关键假设、本地能力清单 | Markdown 片段 | 0 次检索 | 是 |
| 第 1–2 分钟 | 研究问题清单 + 检索关键词组 + 一级来源候选池（先给 5–10 条） | 表格 | 1 次一级广度检索 | 是 |
| 第 2–3 分钟 | 领域认知地图骨架（分支 + 每分支待补证据位） | 大纲/结构图 | 0 次新增检索 | 是 |
| 3 分钟后 | 证据条目逐条落库、报告与离线 HTML 成型 | 文件产物 | 按阶段累加 | — |

**门槛检查**：
- [ ] 第一个可见结果不依赖阶段 2 完成。
- [ ] 3 分钟内至少交付 1 个"用户可以直接判断对不对"的东西。
- [ ] 若首次检索失败，仍能给出简报草案（不让用户干等）。

## 2. 体验流程

| 步骤 | 用户动作 | 系统动作 | 用户此刻的问题 | 本步消除的不确定 | 失败降级 |
|---|---|---|---|---|---|
| S1 提需求 | 说清 `{research_domain}` 与用途 | 复述意图、提 ≤3 个澄清问题 | "它理解对了吗？" | 意图是否对齐 | 意图模糊 → 先给假设版简报，标注待确认 |
| S2 看简报 | 确认范围与排除项 | 生成简报草案 | "范围会不会太大/太小？" | 范围边界 | 用户不改 → 按默认假设继续并记录 |
| S3 看候选池 | 挑掉明显不相关来源 | 一级广度发现（`tvly` 全球域 + `mcp__metaso__metaso_web_search` 中文域） | "这些来源靠谱吗？" | 来源覆盖度 | 候选不足 → 换关键词再跑一轮 |
| S4 等待深化 | 看进度与已落库证据 | 二级深度核对（`mcp__metaso__metaso_web_reader`、`tvly extract`） | "现在到哪一步了？" | 进度可见 | 取不到全文 → 记录原因、找替代源 |
| S5 看反证 | 提出自己知道的反例 | 反证验证 + 三级缺口补充（微信公众号：秘塔搜索限定 `site:mp.weixin.qq.com` + `metaso_web_reader` 取全文） | "有没有相反证据？" | 结论稳健性 | 缺口补不上 → 结论降级为待验证 |
| S6 收交付物 | 打开 Markdown 与离线 HTML | 双格式输出（内容 100% 一致） | "我能直接用吗？" | 可直接引用 | 两版不一致 → 从同一 payload 重渲染 |
| S7 归档溯源 | 抽查链接、看归档信息 | 阶段 5 归档与溯源备案 | "这些结论我能回溯吗？" | 可追溯 | 链接失效 → 标注并记录 |

## 3. 当前边界

| 边界类别 | 现在做 | 现在不做 | 触碰边界时的处理 |
|---|---|---|---|
| 范围 | `scope.in`：{纳入范围} | `scope.out`：{排除范围} | 超出范围的需求 → 单独立项，不塞进本轮 |
| 读者 | 面向 `{audience}` | 不做多读者版本分化 | 需要第二读者 → 在报告内加"给 {stakeholder_view} 的要点"小节 |
| 深度 | 核心结论带反证或"未找到反证"说明 | 不做穷尽式文献综述 | 深度不足 → 在证据充分度评级里降级 |
| 来源 | 公开可检索来源 + 三级搜索协同 | 不采信内部非公开数据（除非用户提供并标注） | 用户给内部材料 → 单独标注来源类型 |
| 形式 | Markdown 报告 + 单文件离线 HTML | 不做在线托管、不做定时更新 | 需要在线 → 超出本包边界，另做交付 |
| 成本 | 秘塔每次检索约 3 积分、Tavily 有额度上限，预算内完成 | 不做无限次检索 | 预算将超 → 先回报再决定 |
| 时效 | 标注提取时间与数据截止日 | 不承诺后续变化 | 需要跟踪 → 交给下一轮运行 |

## 4. Loop Closure Board（闭环看板）

每轮运行结束后更新一行。**决策列只能填** `writeback` / `proposal` / `none-with-reason` / `blocked`，并必须写理由。

| 轮次 | 运行类型 | 输入（`research_domain` + `deliverable_target`） | 可见结果 | 证据（结构/产物/运行） | 发现的问题 | 决策 | 理由 | 写回到哪个文件 | 下轮复用键 |
|---|---|---|---|---|---|---|---|---|---|
| R-1 | 首次跑通 | {领域} / {目标} | 简报 + 候选池 + 报告骨架 | 运行记录 + 产物截图/文本 | {问题} | writeback | {为什么值得写回} | assets/{模板名} | drc-{领域缩写}-{YYYYMMDD}-v1 |
| R-2 | 回归运行 | {领域} / {目标} | {结果} | {证据} | {问题} | proposal | 改动面大，先提建议不动包 | — | drc-{缩写}-{日期}-v2 |
| R-3 | 边界运行 | {领域} / {目标} | {结果} | {证据} | 触到"当前边界"中的 {项} | none-with-reason | 属预期边界外，非缺陷 | — | drc-{缩写}-{日期}-v3 |
| R-4 | 受阻塞运行 | {领域} / {目标} | 无 | 工具不可用记录 | 三级搜索路线不可用 | blocked | {具体阻塞条件} | — | drc-{缩写}-{日期}-v4 |

**写回规则**：
1. 只有"可复用的学习"才写回（新失败模式、新校验点、新模板字段、新降级路线）。
2. 一次性现象不写回，写进 `none-with-reason` 并说明。
3. 涉及大幅改结构时先出 `proposal`，不直接改包。
4. 同一个阻塞条件连续 ≥3 轮未解，才可判定 `blocked` 并写明具体条件。

**看板健康检查**：最近 N 轮中是否有 `writeback` 以外的决策记录？是否出现同一问题重复 ≥2 次却仍无写回？如是，说明闭环未生效。
